# Что vpsFocus делает на вашем сервере

Опись всего, что приложение vpsFocus выполняет на сервере по SSH.

Каждый скрипт ниже — файл в каталоге `scripts/` (в репозитории приложения —
`apps/desktop/src-tauri/scripts/`, рядом с этой описью). Приложение вшивает
его в сборку как есть (`include_str!`) и добавляет к нему только две вещи:

* **параметры** — строки `ИМЯ='значение'` перед текстом файла. Значение
  всегда в одинарных кавычках; подстановки внутрь текста нет;
* **данные** там, где они есть: содержимое заливаемых файлов (`put.sh`) и
  SQL карточек (`sqlite-cards.sh`). Они встают на место строки-метки
  `@ИМЯ@` и состоят только из вызовов функций, объявленных в самом файле,
  с heredoc или строкой base64.

Скрипты отдаются на stdin (`sh -s`) и на диск сервера не попадают. Две
короткие команды — `probe.sh` и `restore-upload.sh` — уходят строкой
команды SSH, потому что stdin у них занят (у второй по нему едет архив
копии); секретов в них нет.
Пароль `sudo` не спрашивается никогда: вход под root — без sudo, иначе
`sudo -n`, и отказ — это отказ, а не ожидание ввода.

Сторожа описи — тесты `scripts.rs`: каждый файл здесь назван в описи и
вшит в приложение; каждый модуль приложения, который ходит на сервер, назван
ниже; текста скрипта строкой в коде приложения нет.

## Что ещё попадает на сервер, кроме этих скриптов

| Что | Где | Как |
|---|---|---|
| Установочные файлы: `install.sh`, `update.sh`, `rollback.sh`, шаблоны, `bundle.json`, `bundle.sig` | `installer-bundle/versions/<версия>/` | заливает `stack-launch.sh`; подпись проверяет приложение до заливки |
| Проверка перед установкой `dry-run.sh` | `installer-bundle/shared/scripts/` | из бандла; та же копия вшита в приложение (`dryrun.rs`). ТОЛЬКО ЧТЕНИЕ |
| Агент | `agent/` | образ `ghcr.io/zaevlad/vpsfocus-agent` по дайджесту из шаблона compose |
| Caddy с модулями | `images/caddy/` | образ `ghcr.io/zaevlad/vpsfocus-caddy` по дайджесту |
| Umami, Postgres | чужие образы | закреплены дайджестом в шаблоне compose |

## Скрипты

**Только чтение** — скрипт ничего не меняет на сервере.

| Файл | Когда запускается | Что делает |
|---|---|---|
| `probe.sh` | добавление сервера, каждое подключение | имя, ОС и архитектура сервера. Одной командой, не скриптом. ТОЛЬКО ЧТЕНИЕ |
| `stack-status.sh` | экран установки, многие экраны сервера | работают ли контейнеры мониторинга, его версия, состав проектов. ТОЛЬКО ЧТЕНИЕ |
| `stack-read-state.sh` | перед установкой, обновлением, заменой сертификата | пароли и списки уже стоящего мониторинга, чтобы не затереть их. ТОЛЬКО ЧТЕНИЕ |
| `stack-launch.sh` + `stack-launch-body.sh` + `put.sh` | «Установить», «Обновить» | заливает файлы в `/opt/vpsfocus` и запускает `install.sh` или `update.sh` из бандла, отвязанным от сессии SSH. **Меняет** `/opt/vpsfocus`, `/opt/vpsfocus.run` |
| `stack-follow.sh` + `stack-follow-body.sh` | пока идёт установка | читает журнал установки с нужного байта. ТОЛЬКО ЧТЕНИЕ |
| `stack-run-state.sh` | открытие экрана установки | есть ли незаконченная установка. ТОЛЬКО ЧТЕНИЕ |
| `stack-run-discard.sh` | итог установки прочитан | удаляет каталог своего прогона `/opt/vpsfocus.run` |
| `stack-cleanup.sh` (под `lock-opt.sh`) | «Убрать следы» прерванной установки | зовёт `rollback.sh`, удаляет каталог прогона и — только если установка ничего не успела записать — каталог стека |
| `lock-opt.sh` | обёртка восстановления, сноса и уборки | замок `flock` на `/opt`: две операции над мониторингом разом не идут |
| `stack-restart.sh` | «Перезапустить» в «Диагностике» | перезапускает один контейнер мониторинга (postgres, umami, caddy, agent) |
| `stack-own-certificate.sh` | экран сертификата | читает свой сертификат мониторинга (не ключ) — срок и имена. ТОЛЬКО ЧТЕНИЕ |
| `stack-replace-certificate.sh` + `put.sh` | «Заменить сертификат» | кладёт новую пару в `/opt/vpsfocus/tls`, проверяет её, перезапускает Caddy мониторинга; при любом провале возвращает прежнюю |
| `stack-capacity.sh` | «Запас ресурсов», по кнопке | сколько места заняли тома мониторинга и сколько свободно. ТОЛЬКО ЧТЕНИЕ |
| `backup.sh` | «Скачать копию» | архив с дампом аналитики и файлами мониторинга (в том числе паролями) уходит на компьютер человека; временный каталог удаляется |
| `restore-upload.sh` | «Восстановить из файла» | принимает архив копии в `/opt/vpsfocus/.restore`. Одной командой, архив — на stdin |
| `restore-fetch.sh` | «Восстановить из хранилища» | сервер сам скачивает копию по ссылке, подписанной его агентом |
| `restore.sh` (под `lock-opt.sh`) | восстановление | останавливает Umami, заменяет базу аналитики дампом из копии, поднимает Umami; копию удаляет |
| `wipe.sh` (под `lock-opt.sh`) | «Удалить сервер» с галочкой «снести мониторинг» | снимает выданный нами доступ к логам, зовёт `rollback.sh --force`, удаляет `/opt/vpsfocus`. Docker не удаляет никогда |
| `log-access.sh` | экран логов: «Разрешить чтение», «Снять доступ» | **за пределами нашего каталога**: ACL группе `adm` на каталог логов — с согласия человека и обратимо; список выданного — в `/opt/vpsfocus/log-access.list`. Действие `list` — ТОЛЬКО ЧТЕНИЕ |
| `read-file.sh` | экраны настроек | читает файл настроек мониторинга и его хеш. ТОЛЬКО ЧТЕНИЕ |
| `write-file.sh` + `write-in-place.sh` | сохранение настроек, проектов, ключевых адресов, общего календаря | записывает один файл в `/opt/vpsfocus` поверх свежего, при надобности пересоздаёт контейнер агента |
| `calendar-read.sh` | календарь | общий календарь команды `/opt/vpsfocus/calendar.json`. ТОЛЬКО ЧТЕНИЕ |
| `team-read-secrets.sh` | подключение к мониторингу, который поставил коллега | пароли мониторинга с сервера — в хранилище ОС этой машины. ТОЛЬКО ЧТЕНИЕ |
| `discovery-prelude.sh` + `discovery.sh` + `cert-paths.sh` | «Найти сайты» | домены из конфигов nginx, Apache, Caddy, в том числе в Docker (`docker inspect`, без входа в контейнер). ТОЛЬКО ЧТЕНИЕ |
| `certscan.sh` + `cert-paths.sh` | «Найти сертификат» | пары «сертификат — ключ», уже лежащие на сервере (ключ — только путём). ТОЛЬКО ЧТЕНИЕ |
| `certscan-read-pair.sh` | выбран найденный сертификат | читает выбранную пару; ключ уходит обратно на этот же сервер. ТОЛЬКО ЧТЕНИЕ |
| `server-check.sh` | «Безопасность» → «Проверить сервер» | файрвол, порты, SSH, обновления, перезагрузка. ТОЛЬКО ЧТЕНИЕ, не оставляет даже служебных следов (проверено `find / -newer`) |
| `containers.sh` | «Проверить контейнеры» при разборе сбоя | `docker ps -a` и `docker inspect`. ТОЛЬКО ЧТЕНИЕ |
| `docker-inspect.sh` | «Данные сайта», база в Docker | адрес контейнера базы для туннеля. ТОЛЬКО ЧТЕНИЕ |
| `sqlite-cards.sh` | «Данные сайта», база SQLite | запросы карточек: `sqlite3 -readonly -safe`, предел строк и времени. ТОЛЬКО ЧТЕНИЕ |
| `put.sh` | внутри запуска установки и замены сертификата | функция заливки файла: права до появления файла, подмена целиком |

Кроме скриптов, приложение открывает **туннели SSH** — они команд не
исполняют, но дают приложению дорогу к портам сервера, слушающим только
`127.0.0.1`:

| Куда | Зачем |
|---|---|
| API агента | экраны мониторинга; по нему же приложение запускает проверки, обход ссылок, замеры, SEO-аудит, копию в хранилище, режим работ. Что агент делает по этим запросам — его код, `agent/` |
| Umami | аналитика |
| База сайта | «Данные сайта»: запросы под пользователем, которого завёл человек |
