# agent

Лёгкий агент, живущий на VPS клиента рядом с его сайтом. Сделан в **спринте 7**,
в **спринте 13** научился проверять битые ссылки.

Четыре занятия, каждое в своём ритме:

- раз в минуту снимает показатели **сервера** (не контейнера) и кладёт в SQLite;
- раз в несколько часов проверяет сроки **доменов** и **сертификатов**;
- раз в сутки обходит сайты и проверяет **битые ссылки**;
- когда что-то не так — сам пишет письмо, в Telegram, Slack, Discord или на заданный адрес (вебхук).

Приложение агентства ходит к нему по HTTP через SSH-туннель. Наружу агент не
смотрит и никуда ничего не отправляет, кроме уведомлений по адресам, которые
задал пользователь.

## Почему он вообще есть

Всё это можно было бы делать из десктопа. Но домен истекает и диск кончается
независимо от того, открыто ли приложение, а открыто оно бывает пару раз в
неделю. Агент — единственная часть системы, которая работает, когда никто не
смотрит.

## Как устроен

```
cmd/agent/          главный цикл: замеры, проверки, рассылка
internal/config/    окружение + список сайтов с диска
internal/metrics/   /proc и statfs хоста, смонтированные внутрь только на чтение
internal/checks/    RDAP, whois, TLS и правила тревог
internal/links/     краулер сайта + запуск lychee (спринт 13)
internal/store/     SQLite: замеры, результаты проверок, отчёты о ссылках, тревоги
internal/notify/    SMTP, Telegram, Slack, Discord и вебхук
internal/httpapi/   HTTP на петле, аутентификация по токену
```

**Язык — Go**, решено вместе со стеком backend в спринте 3: один статический
мультиархитектурный бинарник, десятки мегабайт памяти на машине, где уже
крутится сайт клиента.

## Битые ссылки

Lychee — линк-чекер, а не краулер: он проверяет ссылки на переданных ему
страницах, но сам по сайту не ходит. Поэтому обход делает агент (`internal/links`):
от главной страницы по внутренним ссылкам, с потолком глубины и числа страниц,
а готовый список страниц уезжает в lychee списком входов. Бинарник лежит в
образе агента (`third-party/lychee` — тексты его лицензий Apache-2.0/MIT).

Круг идёт в фоне: ручной запуск отвечает сразу, а приложение опрашивает
`GET /links`, пока крутится флаг `running`. История кругов хранится в SQLite,
на сайт держатся последние 30 отчётов.

## Что задаётся снаружи

Секреты и пороги — через `agent.env` (права 600, владелец root), список
сайтов — отдельным файлом. Разделение не случайно: секреты меняются редко и
стоят перезапуска контейнера, а список сайтов меняется каждый раз, когда
агентство заводит клиенту новый домен, и агент перечитывает его сам.

| Переменная | Зачем |
|---|---|
| `AGENT_TOKEN` | Доступ к API. Пустой — агент не стартует |
| `SMTP_*` | Почта. Пусто — письма не отправляются |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | Telegram. Пусто — сообщения не отправляются |
| `SLACK_WEBHOOK_URL`, `DISCORD_WEBHOOK_URL`, `WEBHOOK_URL` | Адреса «входящих вебхуков» Slack и Discord и произвольный адрес (с 0.21.0). Только `https` и только в интернет: на сам сервер и во внутреннюю сеть агент не пойдёт, перенаправлений не выполняет. В шаблоне бандла ключей нет — строки дописывает приложение. Пусто или негодный адрес — канал выключен |
| `NOTIFY_MUTED` | `1` — уведомления с этого сервера выключены: ни тревог, ни недельного отчёта; проверочное по кнопке уходит. Пусто — включены (с 0.20.0) |
| `ALERT_DISK_PERCENT`, `ALERT_CERT_DAYS` | Пороги тревог |
| `ALERT_DOMAIN_DAYS` | Ступени напоминаний о домене через запятую: `30,14,7,1`. Письмо уходит один раз на каждой ступени и ни одного между ними. Одно число — тот же список из одной ступени |
| `LOG_ALERT_THRESHOLD`, `LOG_ALERT_WINDOW_MINUTES` | Всплеск 5xx: сколько за окно — повод написать. Ноль выключает |
| `LOG_NOT_FOUND_THRESHOLD` | Всплеск «страницы нет» за то же окно. Порог свой и выше: 404 — это ещё и фон от ботов. Только свод, писем по нему нет |
| `AGENT_SAMPLE_INTERVAL`, `AGENT_RETENTION`, `AGENT_CHECK_INTERVAL` | Ритм работы |
| `LINK_CHECK_INTERVAL_HOURS`, `LINK_MAX_DEPTH`, `LINK_MAX_PAGES` | Расписание и пределы краулинга |
| `LINK_MAX_CONCURRENCY`, `LINK_TIMEOUT_SECONDS`, `LINK_EXCLUDE` | Нагрузка на сайт и исключения |
| `LYCHEE_BIN` | Где лежит линк-чекер. По умолчанию `/usr/local/bin/lychee` |

Каталог `/config` монтируется целиком, а не файлом `sites.json`: монтирование
отдельного файла привязывает inode, и атомарная замена перестаёт доходить до
контейнера.

## API

Слушает `0.0.0.0:9101` внутри контейнера, наружу публикуется только на петлю
сервера. Токен обязателен всё равно: в docker-сети рядом стоят чужие по
смыслу контейнеры.

| Метод | Что делает |
|---|---|
| `GET /health` | Жив ли. Единственный без токена — сообщает только факт запуска |
| `GET /metrics?hours=N` | Текущий замер и история |
| `GET /checks` | Последние известные сроки доменов и сертификатов |
| `POST /checks/run` | Прогнать проверки сейчас |
| `POST /notify/test?channel=` | Отправить проверочное уведомление в один канал (`smtp`, `telegram`, с 0.21.0 — `slack`, `discord`, `webhook`); без параметра — во все настроенные. Ответ называет, куда ушло (`channels`) — с 0.20.0 |
| `GET /links` | Отчёты о битых ссылках и флаг идущего круга |
| `POST /links/run` | Запустить круг проверки ссылок в фоне |
| `GET /robots?days=` | Роботы по логам (с 0.22.0): по сайту — кто из списка `internal/bots` назвался в User-agent, сколько раз и когда последний, прочие роботы числом, обращения сканеров и ответы 200 на `.env`/`.git`. Хранятся счётчики «сутки, сайт, имя» — ни строк User-agent, ни адресов |

## Сроки доменов: два пути

Сначала **RDAP** — он отдаёт разобранный JSON, а адрес реестра берётся из
загрузочного файла IANA. Но у доброй половины ccTLD его нет вовсе: `.ru`,
`.io`, `.de`, `.su` в реестре отсутствуют. Для них остаётся **whois** —
текст, который приходится разбирать построчно, зато он есть везде. Сервер для
зоны спрашивается у `whois.iana.org`: свой список устареет молча.

Зона, где не работает ни то ни другое, оставляет срок неизвестным — и агент
об этом **не** пишет. Письмо раз в сутки о том, что мы чего-то не знаем,
приучает не читать письма.

## Тревоги

О новой беде — сразу, о старой — не чаще раза в сутки, о том, что
починилось, — один раз. Состояние помнится в SQLite, поэтому перезапуск
агента не превращается в новую волну писем.

Из показателей сервера тревожит только **диск**: память и процессор скачут и
приходят в норму сами, а кончившийся диск не рассасывается и роняет сайт
клиента.

## Сборка

```powershell
.\build.ps1 -Load   # локально, под эту машину — для тестов против стенда
.\build.ps1 -Push   # amd64 + arm64 в реестр
```

Собирается у нас, а не на VPS клиента: сборка тянет модули Go и падала бы на
сервере с закрытым исходящим трафиком — причём уже после того, как мы
поставили туда Docker.
