# Код vpsFocus, который работает на вашем сервере

[English version](README.md)

[vpsFocus](https://vpsfocus.xyz) — приложение для компьютера, которое ставит
аналитику и мониторинг на **ваш** сервер по SSH. Обещание простое: читаем, но
не меняем ваши сайты, а данные посетителей остаются на вашем сервере.

Этот репозиторий позволяет проверить обещание, а не верить на слово. Здесь
**всё, что vpsFocus кладёт на ваш сервер или выполняет на нём**:

| Каталог | Что это |
|---|---|
| `bundle/<версия>/` | Установочные файлы ровно в том виде, в каком их получает сервер: `install.sh`, `update.sh`, `rollback.sh`, шаблоны, подписанная опись `bundle.json` и её подпись `bundle.sig` |
| `bundle/shared/` | `dry-run.sh` — проверка готовности сервера перед установкой, только чтение |
| `scripts/` | Все остальные скрипты, которые приложение выполняет на сервере по SSH (поиск сайтов, копии, проверка безопасности…) |
| [`SERVER-SIDE.md`](SERVER-SIDE.md) | Опись: каждый скрипт — когда запускается, что читает, что меняет |
| `agent/` | Исходники агента мониторинга (Go) и его `Dockerfile` |
| `images/caddy/` | `Dockerfile` нашей сборки Caddy (ограничение частоты и модули DNS) |
| `keys/release.pub` | Публичная половина ключа, которым подписана каждая версия |
| `tools/verify/` | Проверка версии одной командой |

Сама аналитика — [Umami](https://github.com/umami-software/umami), база —
PostgreSQL: их официальные образы, закреплённые дайджестом в
`docker-compose.yml.tpl`.

## Чего здесь **нет** — честно

* **Приложение для компьютера закрыто.** Каждый скрипт здесь можно прочитать,
  но по одному этому репозиторию нельзя проверить, что закрытое приложение
  шлёт именно их. Внутри приложения они собираются из этих же файлов, и
  автоматические тесты падают, если приложение выполняет скрипт, которого
  нет в `SERVER-SIDE.md`. Со
  своей стороны вы видите все выполненные команды в `auditd` или журнале
  `sudo` своего сервера.
* **Сайта и сервера vpsFocus** (аккаунты и необязательная внешняя проверка
  доступности) здесь нет: на вашем сервере они не работают.
* **Версий старше первой опубликованной** здесь нет. Если на сервере стоит
  старая, приложение предложит обновиться — после этого версия будет
  опубликованной.
* **Первый тег, `bundle-0.27.0`, неточен для `agent/` и `images/caddy/`.**
  Его образы (агент 0.22.0, Caddy 2.11.4-rl2) собраны до появления этого
  репозитория, из исходников, которые отличаются от тега только пятью
  комментариями в коде и закреплениями, добавленными в Dockerfile: модули
  Caddy закреплены ровно теми версиями, что внутри образа rl2, базовые образы
  — дайджестами (с какими дайджестами шли те сборки, не записано). Код на Go
  тот же. Начиная с версии 0.28.0 CI проверяет, что каждый образ собран
  ровно из дерева тега.

## Что полезно знать, прежде чем читать

* **Агент видит весь диск сервера — только на чтение** (`/:/host/root:ro` в
  `docker-compose.yml.tpl`). Это нужно для логов и конфигов веб-сервера, места
  на диске и имени сервера. Наружу он не отправляет ничего, кроме уведомлений,
  которые вы настроили (почта, Telegram, Slack, Discord, вебхук).
* За пределами своего каталога `/opt/vpsfocus` приложение меняет ровно две
  вещи, обе с вашего согласия и обратимо: правило файрвола для порта
  мониторинга (`install.sh`) и, если вы нажали кнопку, право группы `adm`
  читать каталог логов (`scripts/log-access.sh`).
* Комментарии в коде — по-русски. Некоторые ссылаются на внутренние документы
  проекта (`misc/…`), которые не публикуются.

## Как проверить версию

Каждая версия — один коммит и тег `bundle-<версия>`. Экран установки в
приложении называет версию и даёт ссылку на её тег.

**1. Подпись и файлы** (нужен [Go](https://go.dev/dl/)):

```sh
git clone https://github.com/zaevlad/vpsfocus-server && cd vpsfocus-server
git checkout bundle-0.28.0
go run ./tools/verify -version 0.28.0
```

Проверка убедится, что `bundle.sig` — годная подпись `bundle.json` ключом
выпуска, что `bundle.json` перечисляет ровно файлы версии с верными SHA-256 и
что каждый образ закреплён дайджестом.

Подпись можно проверить и стандартной программой
[minisign](https://jedisct1.github.io/minisign/). `bundle.sig` — это подпись
minisign, ещё раз закодированная в base64:

```sh
base64 -d bundle/0.28.0/bundle.sig > /tmp/bundle.minisig
minisign -V -p keys/release.pub -m bundle/0.28.0/bundle.json -x /tmp/bundle.minisig
```

**2. Сравнить с тем, что получил ваш сервер.** Скачайте архив, который
скачивает приложение, и сравните файл за файлом:

```sh
curl -fsSLo bundle-0.28.0.tar.gz https://vpsfocus.xyz/installer/bundle/0.28.0
go run ./tools/verify -version 0.28.0 -archive bundle-0.28.0.tar.gz
```

**3. Сравнить образы.** `bundle/<версия>/docker-compose.yml.tpl` закрепляет
каждый образ дайджестом; на сервере `docker inspect` показывает те же. Начиная с
версии 0.28.0 наши образы собирает GitHub Actions этого репозитория с
[аттестацией происхождения](https://docs.github.com/actions/security-for-github-actions/using-artifact-attestations),
и тогда `gh attestation verify oci://ghcr.io/zaevlad/vpsfocus-agent@sha256:… --repo zaevlad/vpsfocus-server`
доказывает, из какого коммита собран образ. До тех пор образы агента и Caddy
собраны из исходников этого репозитория на машине разработчика.

## Ключ выпуска

Отпечаток: **`337F561861A23810`** (идентификатор ключа minisign). Это тот же
ключ, которым подписаны обновления самого приложения; приложение не ставит
версию без годной подписи. Тот же отпечаток опубликован на
[vpsfocus.xyz](https://vpsfocus.xyz/ru/server-code) и в
[SECURITY.md](SECURITY.md). Если ключ когда-нибудь сменится, он сменится во
всех трёх местах с датой и причиной.
